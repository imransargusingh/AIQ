## Definition of done (exit gate)
- [ ] Single clear responsibility; boundaries and contracts named.
- [ ] **Data model settled first** (`domain-and-data-modelling.md`): the aggregates named with their roots and **the one invariant each protects** (drawn by invariants, small, referenced by identity); the **durable representation** chosen and recorded as an ADR; **grain declared** for every fact/measure/projection; **additivity classified**; **history rule decided per attribute** (Type-1 recorded as a decision to discard history); **derive-don't-store** applied with every materialised derivation labelled a rebuildable cache with an equality test; append-only/interval invariants **enforced and tested** (incl. a test that attempts a forbidden update, and a rebuild test if rebuildability is claimed); every persisted field has a **writer and a compute reader**; any migration is expand-migrate-contract with a non-guessing backfill (Data & Persistence Architect's hard veto).
- [ ] **Change-surface list written down** — store → model → service → projection/wire → client type → UI → compute reader (`end-to-end-integrity.md` E7).
- [ ] **Placed in the delivery phasing**: the vertical slice this component serves named; mock-substitutable seams identified so the slice deploys end-to-end at its phase.
- [ ] Local conventions established and conformed to (or deviation recorded).
- [ ] Every consumed contract established; **unfamiliar ones spiked**; sources cited at the boundary.
- [ ] Every pattern **named and justified**; survives both Patterns Expert and Simplifier.
- [ ] **Solution-Selection Ladder climbed** (L1): the smallest correct idiom chosen; no new dependency for what stdlib / the platform / a few owned lines do; bounded simplifications recorded as `simplify:` markers (ceiling + upgrade trigger).
- [ ] **Failure-mode analysis complete**: modes derived from the design choices across the input/dependency/concurrency/state/resource/time categories, each with an explicit disposition (prevent / detect / mitigate / recover / accept); accepted modes carry rationale + residual risk; handled modes appear in the test plan (SRE + Test Architect).
- [ ] **Adversarial analysis complete**: trust boundaries identified; STRIDE walked per boundary; every threat dispositioned (mitigate / transfer-named / accept-with-rationale); mitigations carry negative security tests in the test plan (Security & Identity Architect's hard veto).
- [ ] **Privacy analysis complete**: LINDDUN walked over every personal-data flow with dispositions, data categories, retention, and rights paths — or the explicit no-personal-data line (Privacy & Data Governance veto).
- [ ] **UI design complete (if the component has an interface)**: medium + platform guidelines named; token references / new tokens (no arbitrary values); key screens with hierarchy; **complete per-component state set incl. empty/loading/error**; motion + reduced-motion; real in-voice copy; medium adaptation; WCAG 2.2 AA + performance budget; and for AI UIs the named HAX guidelines and Shape-of-AI patterns with wrong-answer/uncertainty designed (UI Standard U13–U20; UX & Accessibility lens's accessibility veto). **For an expert/quantitative surface** (CAD, scientific visualization, notebooks, spreadsheet/financial modelling, simulation, quant terminals), **`technical-ui-design.md`** (TQ1–TQ12) is triggered on top: the §G archetype, perceptually-uniform colormaps (never jet), tabular unit-bearing numerics, uncertainty-first output, provenance and reactive recompute — where a rainbow colormap, a unit-less quantity or a point estimate for a stochastic result is a **correctness** defect, not taste.
- [ ] **Design-language doc** (`DESIGN.md`) produced/updated from `templates/design-language.template.md` — token frontmatter + the floors (contrast audit, complete states, modes, paired Archetype Signature, motion, perf, AI-UX); preview rendered; `design-lint.py` clean (UI Standard U3a).
- [ ] **The UI craft gate is named in the test plan** (`ui-craft-detection.md` CD8): the deterministic detector (`ui-craft-gate.py`) runs against the built surface as a rung-2 automated control, with the CD12 severity floors (accessibility Major-minimum / Blocker under an obligation; token discipline Major-minimum) — because a craft rule that lives only in prose is a memoir, not a control (`continuous-improvement.md` CI6). **Any generated asset** is planned to `ui-visual-assets.md`: committed not linked (VA4), manifest + alt text + disclosure (VA12–VA13), budget and perf floors (VA10, VA14), and no likeness or personal-data egress (VA9 — Privacy veto).
- [ ] **Rollups current**: `docs/security/threat-model.md` and `docs/security/privacy-review.md` exist, link `documents` to this design, and their generated registers were refreshed via `docs-graph.py rollup`.
- [ ] **Every** triggered Testing Strategy directive enumerated in the test plan (D0 + the union); none skipped without a recorded deviation; every promised behavior has a verification path (Test Architect — forcing function, hard veto).
- [ ] **Telemetry designed to the Observability Standard**: spans, trace-correlated structured-log events, stable error codes, RFC 9457 responses (HTTP), and metrics named (O1–O13); load-bearing telemetry has a planned test (SRE).
- [ ] Hard vetoes (Security, Distributed Systems, Test Architect) resolved or deviated; authors did not self-clear.
- [ ] Confidence ledger updated; residual risk stated.
- [ ] **Status table emitted**: completed / remaining / best next action.
