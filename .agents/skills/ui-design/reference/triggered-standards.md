## Triggered standards (map the surface, apply the union)
Modes are **mutually exclusive** — you are running exactly one. The standards below are **orthogonal and composable**: any combination can be true at once, each applies on top of whichever mode you are in, and several often fire together (a CFD post-processing tool with a generated hero image trips two). This is the **Testing-Strategy trigger mechanism** (`testing-strategy.md` §3) applied to the interface, and it carries the same force: **map the surface against every row, apply all matching directives as a union rather than the first match, and treat a triggered-but-unmet directive as a gap the gate catches** — never a stylistic nicety to skip. Map at **Stage 1**, not at the gate: a trigger that reshapes archetype selection is worthless discovered in the definition of done.

**Unconditional floor (every run, every mode).** `ui-interaction-design.md` U1–U20 (tokens, complete states, motion, copy, WCAG 2.2 AA, performance) · `ui-design-craft.md` DX1–DX25 (direction, fidelity ladder, harness, critique rubric) · `ui-craft-detection.md` CD1–CD20 (the deterministic control) · `specification-standards.md` S2/S7 (the UX layer is settled before the Surface, or this is a block).

| Trigger | The surface… | Standard | What it changes, and where |
|---|---|---|---|
| **UI-T1** | serves an **expert working with quantities** — CAD, scientific/engineering visualization, computational notebooks, spreadsheet or financial modeling, simulation and risk, quant terminals | **`technical-ui-design.md`** (TQ1–TQ12) | **Stage 1:** the archetype comes from catalog **§G (G1–G6)**, not A–F — picking a bento dashboard for a parametric modeller is the archetype defect, not a styling one. **Stage 3:** perceptually-uniform colormap with a legend (**never jet/rainbow**), tabular right-aligned unit-bearing numerics at consistent precision, **uncertainty-first** output, direct-manipulation *and* precision input, provenance, reactive recompute with visible staleness, large-data performance. **Stage 4:** those become critique dimensions. Note the severity: a rainbow colormap (TQ3), a unit-less quantity (TQ2/TQ7) and a point estimate for a stochastic result (TQ5) are **correctness** defects, not taste. |
| **UI-T2** | contains **generated** imagery, persona or motion | **`ui-visual-assets.md`** (VA1–VA22) | **Stage 1:** the optional visual world, *after* the words and *before* the design language — mood never structure (VA6), supplementing never replacing real named references (VA7), and never the interface itself (VA5). **Stage 5:** assets downloaded, optimized, **committed** and referenced by relative path, each with a manifest entry carrying verbatim prompt, preset, cost, **alt text** and disclosure. Convenes the **AI Systems Engineer** (non-determinism, cost) and **Privacy & Data Governance** (egress, likeness) — both hard vetoes. |
| **UI-T3** | **fronts a model** | **`ui-interaction-design.md`** U13–U15 (HAX + Shape-of-AI); U15a if usage is metered | **Stage 2:** the **wrong answer and uncertainty are enumerated as first-class states**, alongside empty/loading/error. **Stage 3:** name the applicable HAX guidelines and the Shape-of-AI patterns (Wayfinders, Tuners, Governors, Trust builders, Identifiers). **Stage 4:** the **AI Systems Engineer** attacks it — a model capability with no designed wrong-answer path is a Blocker, and a consequential action with no oversight pattern is a Blocker. Where the feature has a per-use cost, the meter, quota states and upgrade path are part of the surface (U15a). |
| **UI-T4** | ships as a **native client app** — first-slice support: **WPF, WinUI, Avalonia** and **Blazor Hybrid** native shells | `docs/knowledge/native-client-ui-design/` + `templates/native-ui-proof-pack.template.md` + the **Native Desktop** developer lens | **Stage 1:** declare the native medium (`native-desktop` / `blazor-hybrid`), platform (`windows` / `cross-platform` / `other`), framework (`wpf` / `winui` / `avalonia` / `blazor-hybrid` / `other`), distribution channel, accessibility API and HIG source. Missing declaration is a preflight block, not a guessed default. **Stage 3:** produce the native proof pack — keyboard traversal, accessibility tree (UIA/NSAccessibility/AT-SPI or browser DOM + native shell), theme/high-contrast, DPI/windowing, large-list performance, OS integration and distribution trust (signing/SmartScreen/notarization where applicable). Run `xaml-token-lint.py` for WPF/WinUI/Avalonia shell markup and use existing web craft tooling for Blazor Hybrid `.razor`/CSS. **Stage 4:** the Native Desktop lens attacks platform idiom, focus/windowing/DPI, accessibility tree and signing gates. HTML mockups and static craft scans are direction evidence only; they cannot clear native PASS. |

> **A trigger is a claim about the surface, so it is established rather than assumed** (`no-guessing-protocol.md` NG1). "This is not really an expert surface" is a decision with consequences; if it is genuinely borderline, take the higher tier until evidence says otherwise (Rules of the Road §0.2).
