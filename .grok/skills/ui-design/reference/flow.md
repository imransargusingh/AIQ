> Stage detail for **/ui-design** — read from `SKILL.md` at the stage that needs it (progressive disclosure, class CTX-E). This file is the normative text; `SKILL.md` carries the outline.

## Flow (Rigor Protocol, specialized to the interface)

**Stage 0 — Interdict the rush.** **Do not generate a screen.** The single most common failure in agent-produced UI is one pass that decides direction, system and composition together and therefore averages all three into the generic default (`ui-design-craft.md` DX1). No markup, no component, no color until Stage 1 has produced a direction brief. In **review** mode, the equivalent interdiction is: **do not diagnose before you measure** (DX23).

**Stage 1 — OPEN (direction, in words).** Write the **direction brief** (DX5): who this is for and the emotional state they arrive in; the **job-to-be-done**; the **Archetype Signature** chosen from that JTBD (`ui-archetype-grammar.md`, nearest row of `ui-archetype-catalog.md`, deviations noted per G9); **three defining adjectives and their opposites**; **named references** with what specifically is taken from each (DX4 — adapt, never clone); the **anti-goals**; and the constraints (medium(s) + platform HIG, density profile, existing brand assets, accessibility obligation level). Then decide the personality in three moves — **type, color, space** — each with a one-line justification tied to the brief (DX6).

> **Map the triggered standards here, not at the gate.** Walk the trigger table above and **state which rows fire and which do not**, with the reason. This belongs in Stage 1 because the triggers *reshape this stage*: UI-T1 moves archetype selection into catalog §G, UI-T3 adds the wrong-answer and uncertainty states to the inventory you are about to enumerate, and UI-T4 makes a platform HIG authoritative over your instincts. A trigger discovered in the definition of done has already cost you the archetype decision it was supposed to inform.

> **Verify the archetype against the shape of the task, including on an existing screen.** *Reading is parallel; entering is serial.* A dashboard/bento archetype applied to a data-entry task is a rewrite, and finding it at the end of a review wastes the review (`continuous-improvement.md` UX-A).

> **Optional — make the direction concrete with a visual world (`ui-visual-assets.md` VA15).** *After* the brief exists in words and *before* the design language, you MAY generate 2–4 candidate direction boards that render the brief's register (atmosphere, palette temperature, material, era) and let the human pick one. The order is fixed and the constraints are hard: generated imagery informs **mood only, never structure** (VA6 — archetype and IA come from the grammar and the UX layer); it **supplements, never replaces, real named references** (VA7 — a generated image is evidence of nothing); and you **never generate the interface itself** (VA5 — no screenshots, panels, charts or icon sets; image models render illegible text and invented controls). Record the chosen board's verbatim prompt, model and preset in `DESIGN.md`, and commit the image (VA4 — provider results expire in 7 days, and a re-rolling asset is non-determinism in a deterministic artifact).

**Stage 2 — INTERROGATE.** Drill the brief with precise questions: *Clarification* — what exactly is this surface for, and what is it explicitly **not** for; *Assumption* — what are we assuming about the user's device, expertise, data volume, and state on arrival; *Cause/Effect* — if we choose this archetype, what does it force (navigation, pacing, density, feedback) and what does it forbid; *Evidence* — is this pattern established for this job (Jakob's Law, U12) or are we inventing; *Significance* — which single decision here most determines whether this succeeds. Enumerate the **surface inventory**: every screen/component in scope, and for each, its full state set (default / hover / focus / active / disabled / **loading** / **empty** / **error** / success / **overflow**) — the list you will be held to at the gate.

**Stage 3 — EVIDENCE (measure, establish, systematise).**
- **In review/elevate mode, measure before diagnosing (DX23).** Count and record: interactive controls per screen, simultaneous sections/cards, network calls on load, competing focal points, distinct type sizes, distinct colors, modes that do the same job, and the token-vs-arbitrary-value ratio. Run **both linters, which check opposite directions of the same contract** (`ui-craft-detection.md` CD5): `python3 docs/ai-forward-pack/scripts/design-lint.py <DESIGN.md> --strict` **inward** (does every `{token}` reference resolve?), and `python3 docs/ai-forward-pack/scripts/ui-craft-gate.py <surface> --markdown` **outward** — the deterministic 59-rule detector, which reads your `DESIGN.md` natively and reports every off-token color, font, size and radius in the *built* source plus the mechanized generic-tells, hierarchy, motion, copy and overflow rules. Its measurement block **is** the DX23 count: `17 × nested-cards` is a diagnosis where "cluttered" is only a symptom. Also compute the **contrast ratio for every text/surface pairing**.
- **The harness measures the page box before any number (DC-200).** A gating selector that matches the element carrying the harness state (`[data-restore]{display:none}` on `<body data-restore=…>`) hides the whole page while every contrast pair and target size still computes, and a sweep that reads only the verdict strip passes. The template's `audit()` asserts a non-zero frame box first and reports *"page not rendered"* — never a pass — when it is zero; scope every gating selector to the frame (`.window [data-…]`), and any repo sweep over mockups asserts the same box before reading a verdict.
- **Keep screenshots out of the main context (CTX-E, profiler SP-12).** The detector's JSON/markdown output and the harness's in-artifact checks are the measurement; do not `view` PNG captures into the main conversation to "look at" a state — an image costs more than the number it stands for, and one captured session pushed eleven screenshots into a 500k-token context and lost a request to an invalid-image error. Delegate visual inspection, with the image paths, to the **UX & Accessibility** lens as a sub-agent whose context is disposable, and read back its findings.
- **Establish, don't recall.** Platform guidelines, the accessibility obligation, comparable products, and any claim about the existing implementation are established from the source (**open the component file** — E15) and labeled Verified / Inferred / Flagged.
- **Native client proof (UI-T4).** If WPF/WinUI/Avalonia/Blazor Hybrid is triggered, fill `templates/native-ui-proof-pack.template.md`. The minimum proof rows are: platform HIG, keyboard traversal, accessibility tree, Light/Dark/HighContrast or platform theme, DPI/windowing, large-list responsiveness, OS integration and distribution trust. A row marked Verified needs native evidence — UI Automation / Accessibility Insights / Appium / platform inspector / package-signing check / runtime recording as appropriate. A screenshot, HTML mockup or `ui-craft-gate.py` result alone is never native accessibility, keyboard, DPI, windowing or signing proof.
- **Native token/resource check (UI-T4).** For WPF/WinUI/Avalonia shell markup, run `python3 docs/ai-forward-pack/scripts/xaml-token-lint.py <paths>` and fold findings into the rubric as token-discipline findings. Allowed first-slice resource forms are WPF `{StaticResource ...}`/`{DynamicResource ...}`, WinUI `{ThemeResource ...}` for theme-sensitive values, and Avalonia `{DynamicResource ...}`/theme-variant resources. Blazor Hybrid splits: `.razor`/CSS uses existing web token/craft checks; the native shell uses the XAML linter and native proof pack.
- **Build the system before the screens (DX2).** Produce or update the project's **design language** — `DESIGN.md` from `templates/design-language.template.md` (the Stitch format extended with this pack's floors), with the token frontmatter, the **contrast audit at the token layer**, the complete component-state matrix, theme/density modes, the paired **Archetype Signature**, motion + reduced-motion, real UI copy strings, the performance budget, and — for AI surfaces — the HAX/Shape-of-AI rules. Keep it `design-lint.py`-clean and render `templates/design-language-preview.template.html` as the visual catalog.
- **Write the motion inventory** (DX19): every animated moment, its purpose, duration and easing — and cut the purposeless ones.
- **Draft the real UI copy** (DX21): buttons that say what they do, empty states that teach the first action, errors that say what happened and what to do next, confirmations that name the irreversible consequence, numbers with units and precision. Copy is drafted here, never deferred to implementation.
- Maintain the confidence ledger.

**Stage 4 — DISCONFIRM (the gate — critique against the rubric).** Switch to Adversary Mode and run the **critique rubric** (DX22), **structure before surface** (DX24): archetype fit and flow/IA first, then state completeness, then accessibility, then craft. Every finding carries **location · dimension · severity (0–4) · evidence · recommended fix · confidence**, mapped to the pack's severities (4→Blocker, 3→Major, 2→Minor, 1→Nit); an accessibility finding at ≥3 is a **Blocker** under U16 regardless of usability impact. **Fold in the detector's findings**, already translated into rubric shape with the CD12 severity floors applied — accessibility findings are Major minimum (Blocker under an obligation) and token-discipline findings are Major minimum, because U16 and U3/U20 do not negotiate with a linter's defaults. Remember what the detector *cannot* see (CD14): archetype fit, information architecture, whether the hard states exist **at all**, whether the copy is true, whether the focal point is defended — **a clean detector run is a floor, never a verdict** (CD13), and reporting it as "the design is good" is exactly the laundering NG7 forbids. Self-check against the **generic-tells table** (DX3) — each tell is either absent or a deliberate, justified choice; any suppressed rule carries a real reason and a standing suppression is a recorded deviation (CD16). The Simplifier emits its tagged delete-list with a `net: -N` line. The UX & Accessibility lens states **PASS/BLOCK** with its veto-clears-when predicate; **the author does not clear it**. Attack the mockup through the harness: switch every persona, viewport, state, theme and the reduced-motion path, and confirm each is real rather than claimed.

**Stage 5 — CONVERGE (produce the artifacts).**
- **Mockup** — a **self-contained, dependency-free HTML file** at `docs/mockups/<surface>.html` (DX8): one file, no build step, no CDN, opens over `file://`. It renders the **hard states** — empty/first-run, loading (skeleton matching the content shape), error with its real recovery affordance, partial/degraded, and overflow with realistic extreme content (the longest name, the 7-digit number, the negative value, the missing avatar) (DX9, DX16). It ships with the **review harness** (DX10): a control bar switching **persona · viewport · component state · theme/density · capability flags · reduced motion**, plus in-artifact mechanical checks (computed contrast per pairing, undersized targets flagged) (DX11). The harness is review chrome and never ships to production. Start from `templates/mockup-harness.template.html`.
- **Hub node** — `docs/mockups/<surface>.md` carrying the V2 frontmatter and typed links, so the mockup is in the graph (the `.html` is data; the `.md` is the node).
- **Design language** — `DESIGN.md` created/updated, lint-clean, preview rendered.
- **Generated assets (if any)** — every image, persona and clip **downloaded, optimized, committed** under `docs/assets/<surface>/` and referenced by relative path, each with a manifest entry in `DESIGN.md` carrying the verbatim prompt, generator, preset, date, cost, **alt text** and disclosure (`ui-visual-assets.md` VA12–VA14). No provider CDN URL survives in a committed artifact (VA4 — 7-day retention), no real person's likeness or customer data was ever uploaded (VA9), and every clip is in the motion inventory with a reduced-motion fallback (VA17).
- **Oracle strings are quoted from `DESIGN.md`, never retyped (DC-196).** Every user-facing sentence a review's oracle asserts is copied verbatim from the design language's *Copy added by this section* row (the UI copy drafted in Stage 3), and the review names the row. One sentence with two definitions — the artifact's and the oracle's — leaves the implementer to choose, and the choice is invisible until a test fails on the wrong one. A repo's cited-controls check, where it has one, compares the two strings mechanically.
- **Review artifact (review/elevate mode)** — `docs/reviews/ui-<surface>.md` from `templates/ui-review.template.md`: the measurements, the rubric findings, the scorecard by dimension, and a **ranked plan** — must-fix / should-fix-next / worth-doing — with **the single highest improvement-to-effort change named explicitly** (DX25). A review that returns 40 undifferentiated findings gets ignored, and the reviewer owns that.
- **Native proof pack (UI-T4)** — `docs/proof/native-ui-<surface>.md` from `templates/native-ui-proof-pack.template.md` or embedded in the review artifact when the proof is small. It records medium declaration, proof rows, framework-specific rows and release/signing residual risk. Native PASS requires this evidence or explicit Flagged residual risk; a clean web/mockup result is not enough.
- State the residual risk and the flagged unknowns. Where the work changed the UI acceptance criteria, update the spec's Part C rather than letting the artifacts diverge.
