3. Terms

T1. Anthropic, Imran's own use — Low

What the terms say (read):

  • "Advertised usage limits for Pro and Max plans assume ordinary, individual usage of Claude Code and

the Agent SDK." (legal page)

  • The headless page says claude -p is "using the Agent SDK via the CLI", for "scripts and CI/CD".
  • The legal page does not "prevent an end user from signing in to the unmodified Claude Code binary

with their own Claude subscription".

  • Consumer Terms §3(7) bars access "through automated or non-human means, whether through a bot,

script, or otherwise", except via an API key or where Anthropic explicitly permits it.

Reading (Inferred): Imran running his own unmodified Claude Code on his own plan, from a script he wrote for himself, is the individual Agent SDK use the legal page describes. Anthropic documents claude -p for scripts, which reads as the explicit permission §3(7) allows for. AIQ never touches the token. The risk is volume: a background judge that makes many calls is less "ordinary" than a person typing.

Recommendation: keep. Keep the default daily budget small and visible (TR-8 already does this).

T2. Anthropic, giving AIQ to others with subscription sign-in — High

What the terms say (read):

  • "Developers building products or services that interact with Claude's capabilities, including those

using the Agent SDK, should use API key authentication."

  • "Anthropic does not permit third-party developers to offer Claude.ai login into their own

applications, or to route requests through Free, Pro, or Max plan credentials on behalf of their users."

  • OAuth is "designed to support ordinary use of Claude Code and other native Anthropic applications".
  • "Anthropic reserves the right to take measures to enforce these restrictions and may do so without

prior notice."

Reading (Inferred): For anyone other than Imran, AIQ is a product Imran built, it uses the Agent SDK (through claude -p), and it sends prompts AIQ wrote (the judge envelope), not prompts the person typed. A reviewer at Anthropic could read that as routing requests through the person's plan on their behalf. The end-user carve-out covers signing in to the binary; it does not clearly cover another product driving that binary in the background. Imran's position (AIQ works only for the person, on their machine, with their own sign-in) is a fair argument, and the binary is unmodified and no token is handled, which meets the hard rules. But the text points the other way on the Agent SDK point, and the penalty (account action without notice) falls on the user, not on AIQ.

Recommendation: before AIQ goes to anyone else, make the person's own Anthropic API key (or their Bedrock / Agent Platform / Foundry credentials, which the page explicitly allows) the Claude default, and offer subscription sign-in only if Anthropic confirms it in writing (the page names https://www.anthropic.com/contact-sales for questions on permitted authentication). ADR-0007 already says this is a settings change, not a redesign. Imran's own use can stay on his subscription.

Owner decision (Imran, 2026-11-02): keep the person's own Claude subscription (claude -p) as the Claude judge default for all users; the matter is closed. Scope, as Imran stated: this applies only to tasks seen by Claude Code. Tasks from Copilot CLI and VS Code are judged by Copilot through the person's own copilot -p (history-import H5) and are not affected. AIQ's target users will almost exclusively use Copilot, so few judge calls go through this path. The API-key fallback stays opt-in. The finding is recorded as an accepted risk in the threat model.

4. Security

The judge path has five steps: hook → core (local pipe / socket) → store (and spool while the core is down) → judge envelope → provider CLI → schema-checked answer → card. Findings follow that order where possible.

S1. Judge sessions keep copies of task content outside AIQ's delete — Medium

Evidence (read): history-import spec: every copilot -p call saves a session folder, and "AIQ cleans up its own judge session folders after reading the answer only if the person allows it". fact_check.py records each judge session id in ~/.aiq/judge-sessions.txt and does not delete the folder. aiq forget (Phase 1) deletes the store and spool only. Why it matters: each judge call writes a second plain-text copy of the task's prompts into ~/.copilot/session-state, outside AIQ's store. After aiq forget, the person believes their content is gone, but it is still there. That breaks the privacy rule "raw prompts stay on device until the user deletes them" in spirit: they cannot delete them from AIQ. Recommendation: delete AIQ's own judge session folders (by the recorded id) as soon as the answer is read, by default, with a setting to keep them for debugging. aiq forget must also delete any that are left. Decided (Imran, 2026-11-02): delete by default, with a setting to keep them; the history-import spec is updated to match. Claude judge calls already use --no-session-persistence.

S2. No secret redaction — Medium

Evidence (read): no redaction code in crates/ or the specs; prompts are stored as typed (up to 64 KB), spooled as typed, and the judge envelope carries the task's prompts. Why it matters: people paste API keys, connection strings and tokens into prompts. The provider already saw them (same-provider rule), so a judge call adds no new party, but it adds copies: in the store, in the spool, in the provider's retention and a work account's audit log a second time, and in Copilot's saved judge session (S1). The store is plain SQLite (S10). Recommendation: at ingest, before anything is stored, spooled or sent, replace well-known secret shapes with a marker ([secret removed]): provider key prefixes (sk-ant-, sk-, ghp_, gho_, github_pat_, AKIA, xox[bap]-, AIza), private-key blocks, JWTs, and password= / connection-string values. Count removals in aiq status. Keep it a deterministic, tested list (a golden set of canary secrets that must never reach the store, the spool or a judge envelope). This also lowers the risk in S9 and S10 more cheaply than encryption.

S3. Judge env-var name mismatch — Medium

Evidence (read): crates/aiq/src/hook.rs checks AIQ_INTERNAL; ADR-0007, rung-model US-5 and TR-10, and the threat model say AIQ_JUDGE=1. The Phase 0 spike sets neither. Why it matters: the surface spike found copilot -p fires the person's hooks. If the Phase 5 judge is built from the spec and sets AIQ_JUDGE=1, AIQ's own hooks ingest every judge call as a new task: a feedback loop, and another copy of task content in the store. Recommendation: keep AIQ_INTERNAL (code and the test hook_internal_env_ignored already use it) and correct the three docs (done in this PR). Phase 5 adds a test: every judge spawn sets AIQ_INTERNAL=1, and a judge call with AIQ's hooks installed creates no task. Judge-session ids (US-11) stay as the second guard. A side effect: any process that sets AIQ_INTERNAL silences capture; that is same-user software and is accepted (S8).

S4. The Claude judge call is not fully sealed — Medium

Evidence (read): the headless page says that without --bare, claude -p "discovers and loads" hooks, skills, plugins, MCP servers, auto memory and CLAUDE.md "including anything configured in the working directory or ~/.claude". ADR-0007 uses an empty temp folder, --setting-sources user, disableAllHooks, --tools "" and --no-session-persistence, but not --strict-mcp-config; the Phase 0 spike used --strict-mcp-config and cwd = the home folder, which the Copilot docs advise against for their CLI. --bare "is the recommended mode for scripted and SDK calls, and will become the default for -p in a future release", and bare mode "never reads OAuth credentials". Why it matters: with tools off, user MCP servers and plugins should have nothing to act with (Inferred, not tested), but user CLAUDE.md and auto memory still enter the judge's context: that does not leak data (same provider) but makes judgments depend on the person's own instructions. When --bare becomes the default, the subscription path stops signing in. Recommendation: add --strict-mcp-config --mcp-config '{"mcpServers":{}}'; run the judge with --output-format stream-json once per Claude Code release and check the system/init event lists no MCP servers, no plugins and no tools (a measured check, not a reading); keep --system-prompt (it replaces the default prompt). If a release turns --bare on for -p, detect the auth failure, queue, and tell the person (this also argues for T2's API-key default).

S5. Prompt injection into the judge — Medium

Evidence (read): controls TR-3, TR-4, TR-5, T-B5-5: core-built envelope, task content as quoted data, narrow facts to a JSON schema, asked twice, deterministic floors and guardrails, plain-text rendering, no tools, empty working folder. US-7 includes injection gaming cases. fact_check.py parses Copilot's answer leniently (first { to last }). Reading: with no tools and plain-text output, injection cannot run anything or send data anywhere; the worst case is a wrong fact, so a wrong rung or tip shown only to the person. That is the right design. Two gaps: (a) Copilot plugins still load, and MCP servers are disabled only by the names AIQ finds in three config files, so a server from a plugin or another file stays on; --available-tools= should remove its tools too (Inferred, not tested). (b) The Rust judge must validate against the schema, not extract a {…} span. Recommendation: Phase 5 adds a canary test: a fake MCP server and a plugin that log any call; a judge call whose task says "call every tool" must log nothing. Strict schema validation in Rust; a failing answer is discarded (TR-4). Keep the US-7 injection set in the golden set.

S6. Copilot judge prompt on the command line — Medium (Linux/macOS) · Low (Windows)

Evidence (read): fact_check.py passes the whole judge prompt (rubric plus task content) as the -p argument. The Copilot docs say piped input is ignored when -p is given. Why it matters: on Linux and macOS any local user can read another process's arguments (ps, /proc/<pid>/cmdline) unless the system hides them. On Windows other non-admin users usually cannot; same-user software can. Windows also caps a command line at about 32,000 characters, so long tasks fail. The Claude path uses stdin and is not affected. Recommendation: before Phase 5, check whether Copilot CLI accepts the prompt from stdin without -p or from a file (@file or similar; not checked); use that. Until then: Windows only (the alpha platform), cap the envelope well below the limit, and fail closed (queue, never truncate silently).

S7. Windows pipe name can be taken first by another OS user — Low · Medium on shared machines

Evidence (read): ipc.rs gives the pipe a user-only DACL and the S1 spike showed a second listener on an existing name is refused. The name is predictable (aiq-core-<USERNAME>-<hash of path>). connect() does not check who owns the pipe. Why it matters: another account on the same machine can create that name before the core starts. The core then fails to start, and the hook client connects to the other account's pipe and sends it prompt text and the token. On a single-user laptop there is no other account. Recommendation: in connect() on Windows, call GetNamedPipeServerProcessId, open that process's token, and refuse unless its user SID equals the caller's (then spool). Cheap, and it closes the case. Add the negative test to the S1 spike's residual list.

S8. Hook forgery — Low (accepted)

Frames need the per-boot token from a user-only file; the socket directory is 0700 and the Windows pipe is user-only (ipc.rs, paths.rs; the token check is constant-time in server.rs). Same-user software can still forge frames or set AIQ_INTERNAL; it can already read everything AIQ reads. Accepted by Imran on 2026-10-31. Recommendation: keep; revisit if frames ever carry other people's data.

S9. Plain-text spool — Low (accepted)

Owner-only, ≤ 1 MB, removed on drain (spool.rs, tests spool_file_is_owner_only). On Windows the protection is the inherited ACL of %USERPROFILE%, which also grants SYSTEM and Administrators (per the comment in paths.rs; not re-checked on the laptop). Recommendation: keep accepted; S2 removes the worst content from it.

S10. Plain SQLite store — Low for Imran · Medium before others

Already decided: encryption deferred (note-20261031); threat model says revisit "before any alpha user other than Imran installs AIQ". Prompts are kept until the person deletes them, so exposure grows. A lost laptop with BitLocker on is covered by the disk encryption; an unencrypted backup of the profile is not. Recommendation: for other people, ship S2 redaction first (it removes the highest-value content), then make the encryption decision, which is already on Imran's open list. Check aiq forget also removes -wal and -shm (the store code lists them; keep a test).

S11. Copilot experimental mode — Low

Evidence (read): install_copilot.rs sets experimental: true and adds STATUS_LINE, after showing a diff and asking; it records the previous value and uninstall restores exactly that. The Copilot docs do not say what experimental turns on, only that it needs a restart. Why it matters (Inferred): the setting is global. It likely turns on every experimental Copilot feature in every session, not just the status line, and those features can change between releases without notice. Recommendation: the install prompt should say in one line that this turns on all Copilot experimental features, not only AIQ's status line, and that aiq uninstall copilot turns it back off. Re-test each Copilot release whether STATUS_LINE works without experimental, and drop it when it does. Offer "no status line" (tips through aiq show only) for people who decline.

S12. Hooks point at a test build in %TEMP% — Low

From project memory (not re-checked on the laptop): Imran's Claude Code hooks point at %TEMP%\aiq-pr9\...\aiq.exe. Temp clean-up (Storage Sense) can delete it, and the hooks then fail silently. %TEMP% is per-user, so other users cannot replace it. Recommendation: move to a permanent path (already on the open list).

S13. Phase 0 fact-check residue — Low

fact_check.py wrote judge sessions (ids in ~/.aiq/judge-sessions.txt) into ~/.copilot/session-state, and its outputs into ~/.aiq/fact-check. Both hold task content. Recommendation: delete them when the fact-check data is no longer needed (Claude can do it through folder access on request).
