What VS Code's Copilot agent hooks add (Preview)

Per https://code.visualstudio.com/docs/agent-customization/hooks:

  • "VS Code, the GitHub Copilot app, and GitHub Copilot CLI share this harness and its hook format."
  • Events: sessionStart, userPromptSubmitted, preToolUse, postToolUse, preCompact,

subagentStart, subagentStop, agentStop, sessionEnd.

  • User-level hook files are supported: ~/.copilot/hooks/ (or $COPILOT_HOME/hooks/), and inline

hooks in ~/.copilot/settings.json. Repo-level .github/hooks/*.json also exists (AIQ must not use it).

  • Applies to Copilot sessions (Session Target = Copilot). Cloud sessions do not get local hook files.

Ask mode, inline chat and completions are not described as firing hooks.

  • Output to the person is not described for the VS Code harness; command-hook output is ignored for

userPromptSubmitted; postToolUse can add model context (AIQ must not).

  • "Your organization might restrict which hooks can run" (enterprise hook controls).
  • The harness also reads repository .claude/settings.json, so repo hooks (e.g. AI-Forward's) can run

in VS Code Copilot sessions too.

  • An older "Local" harness has its own hooks (Claude-style events incl. Stop with systemMessage

shown to the user), controlled by chat.useHooks; VS Code recommends the Copilot runtime for new hooks (https://code.visualstudio.com/docs/agents/reference/hooks-reference).

Label: Verified (docs). Run-level check pending on Imran's laptop.

2. Copilot CLI

Docs (https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-hooks-reference): same harness and events as above; command hooks may print {"type":"progress","message":…} lines to the CLI timeline ("temporary": true for a transient line); default timeout 30 s. Latest version on npm: @github/copilot 1.0.105 (2026-10-31).

3. Path forward

Result first: AIQ can observe Copilot CLI and VS Code agent sessions with one user-level collector, but Copilot will not show a card. In-the-moment coaching on Copilot needs a surface AIQ owns. Two choices are Imran's (below); the rest follows from the evidence.

  1. One Copilot collector for both surfaces. A single user-level file, ~/.copilot/hooks/aiq.json,

using exec + args (never a shell field), calls the same compiled aiq hook copilot <event> client as Claude Code. It feeds the core from Copilot CLI and VS Code Copilot agent sessions. Never repo-level .github/hooks/. Verified for Copilot CLI; VS Code from docs only.

  1. Subscribe to as few events as possible, because every hook blocks. Phase 2 needs prompts and

turn ends only: userPromptSubmitted and agentStop. That adds roughly 140–240 ms per prompt (Copilot's start-up plus AIQ's client). Tool hooks would add about twice that per tool call, so they wait until a detector needs them (Opportunities 2 and 3). Inferred from the measured parts; the end-to-end figure is not measured.

  1. ADR-0005's Copilot render path is wrong and must change. Rendering via a progress line does

not work. AIQ will not use additionalContext or exit code 2 to get text in front of the person: both act on the agent, and coaching is for the person (ADR-0005 rule 1).

  1. Where Copilot CLI cards show (Imran's choice):
  • a) Copilot CLI's status line (recommended to try first): a one-line nudge such as

AIQ tip: reworded 3× without new details · aiq show, read from the core. It is persistent, in the person's view, and needs no window switch. It is experimental, needs a laptop check, and on Windows a feature flag.

  • b) A desktop notification from the core at `agentStop`: works for any terminal, but it pulls

attention out of the terminal and some work laptops suppress it.

  • c) No in-the-moment card on Copilot CLI: only next-pause and summary coaching.
  1. VS Code renders through the extension. Hooks observe; the extension reads cards from the core

and shows a notification plus a status-bar item. It also adds editor and terminal signals, hosts vscode.lm for the judge, and offers Pause. Ask mode, inline chat and completions stay blind spots. Undocumented on-disk chat session files are a possible later source. Flagged; not a contract.

  1. One hands-on check is still owed: VS Code. About 5 minutes on Imran's laptop, with a temporary

~/.copilot/hooks/aiq-probe.json that only appends to a temp log and is removed straight after. It answers whether the user-level hook fires in a VS Code agent-mode session, and whether any hook output reaches the person there. While the file exists, Copilot CLI sessions also run it (about 150 ms per event).

  1. Budget wording (Imran's call). The spec says a collector adds "≤ 50 ms p95 to any hook it runs

in". On Copilot, the host's own process start (110–210 ms) comes with any hook at all. Proposed wording: AIQ's own client stays ≤ 50 ms p95 (measured 26–34 ms), and the whole hook, including the host's start-up, is measured and shown in aiq status.

Risks

  • VS Code hooks are Preview, and the status line is experimental. Either can change or disappear.
  • Organisation policy can restrict hooks. This laptop already has an admin-forced model.
  • Hook latency on a busy machine had multi-second outliers in the probe. Inferred cause: concurrent

updates.
