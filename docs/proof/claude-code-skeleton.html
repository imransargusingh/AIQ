Claims & evidence

C1. Rewording a request three times gives one card at the next Stop; the card never quotes the prompt

  • Evidence: e2e_reword_three_times_one_card_second_run_held drives the real binary with Claude Code

payloads (4 prompts, then Stop) against a real core; Stop prints exactly one {"systemMessage": "AIQ tip: you've reworded this request 3 times without adding new details.\n…"}. Manual smoke run printed the same line (Linux, debug build).

  • Oracle: asserts the card's first line, Try this:, aiq pause, and that none of the four prompt

texts appear in it. Domain tests pin the threshold: observe_two_reprompts_no_signal (2 → none), observe_three_reprompts_one_signal_with_evidence (3 → one signal, evidence = 4 event ids).

  • Red observed before green: yes for the detector: observe_cue_only_run_scores_half failed on the first

implementation (a repeated "try again" counted as similar), fixed by keeping cue-only prompts out of the request window (DC-001). Mutation testing (below) shows the detector tests fail when the logic is wrong.

  • Laptop: four read-only rewords ("which models are installed on this laptop?" …) in a terminal

claude session gave the card under the 4th reply (screenshot, 8:47 PM); store, screen and aiq show agree on the card id; the card does not quote the prompts.

  • Confidence: Verified (Linux, Windows laptop).
  • Residual risk: detector thresholds (0.6 / 4 words / 3 / 0.75) are uncalibrated pack data (design

assume:); real-data week decides. Observed on real use: the word-overlap check misses natural paraphrases (Imran's first four paraphrases peaked at 0.40) and word forms ("install" vs "installed"). Recorded in the design's laptop findings; not fixed in this slice.

C2. A second qualifying run in the same session is held, also across a core restart

  • Evidence: same e2e test: second run's Stop prints nothing; aiq status shows 1 shown (ok) and

1 hold (session_budget). restart_mid_session_budget_survives, second_ready_card_before_stop_held_one_at_a_time.

  • Oracle: budget is derived from card_delivery rows, and second_delivery_same_session_conflicts_even_bypassing_loop

proves the unique index rejects a second delivery even without the decision loop. e2e_concurrent_stops_deliver_once: 8 parallel Stop hooks → at most one card, and never a second later.

  • Red observed: not separately (tests written with the code); mutation run kills every trigger.rs mutant.
  • Laptop: the real Windows aiq.exe (dadb74d), fed Claude Code hook payloads for one session id in an

isolated AIQ home: models loop → card; shells loop → nothing printed; aiq status: "Signals: 2. Cards: 1 hold (session_budget), 1 shown (ok)". Not watched in the Claude Code UI (a held card prints nothing). In real use a second card in a new claude session showed, as designed.

  • Confidence: Verified.
  • Residual risk: none known for one machine. Cross-surface sessions are Phase 2. Repeating the same

reworded question after a card never fires again in that session (one signal per loop, by design).

C3. The hook fails open within budget and never changes Claude Code's behaviour

  • Evidence: e2e_core_down_stop_exits_zero_within_budget_p95_and_spools (50 Stop runs, core down: exit 0,

no output, 50 spool lines, no token in the spool). Release build, Linux, whole process, 50 runs each: core down p50 2.2 / p95 3.0 ms; core up p50 2.8 / p95 3.8 ms (budget 100 ms; was 50 ms). e2e_random_bytes_never_print_always_exit_zero (0 B to 300 KB of random bytes, both events: exit 0, empty stdout and stderr). Every Stop output is checked by assert_hook_stdout_contract (empty, or one line that is an object with exactly the systemMessage key). UserPromptSubmit output is asserted empty on every call in the e2e suite.

  • Oracle: the stdout contract would fail on any additionalContext, decision, continue or stray

print; the timing assertion fails above 100 ms p95.

  • Red observed: the random-bytes test went red (broken pipe) when stdin was larger than the 256 KB cap;

fixed by draining the rest of stdin (DC-002).

  • Laptop (measurement of record for Windows): whole process, direct exec, release build. Stop core

down: p50 27.5 / p95 70.5 ms (n=50); Stop core up: p50 27.8 / p95 66.8 ms (n=50); UserPromptSubmit core up: p50 27.5 / p95 65.2 ms (n=20). In-process: Stop p95 3.1 ms, UserPromptSubmit p95 1.4 ms. All exit 0. Install self-test on a never-run exe: 344 ms.

  • Confidence: Verified on Linux. Windows: meets the 100 ms p95 budget (Imran raised it from 50 ms

on 2026-11-01, note); nearly all of the time is process start, outside AIQ's code (Inferred: likely security scanning; not measured).

  • Residual risk: one UserPromptSubmit run recorded 4.4 s in-process on the laptop (async hook, so the

prompt was not delayed; 5 s timeout). Cause not yet confirmed; suspected the cold core start just after a rebuild.

C4. At-least-once delivery with idempotent ingest (architecture gate: spool-replay property test)

  • Evidence: spool_replay_any_interleaving_duplication_truncation_same_result (proptest, 48 cases):

any shuffle, duplication and partial-line corruption of the spool gives the same event rows, signal count and decisions as one clean delivery. spool_replayed_twice_one_row_one_signal, insert_event_replay_stores_one_row. e2e_core_down_prompt_starts_core_once_core_survives_and_drains_spool: a prompt hook with the core down starts a detached core, which survives the hook and drains the spool.

  • Oracle: compares full outcomes, not just "no panic"; drain sorts by event_id and de-duplicates.
  • Confidence: Verified (Linux and Windows laptop: 50 core-down Stops spooled and drained once the core

started; a hook started the detached core on real prompts).

  • Residual risk: a spool over 1 MB drops oldest lines (Spool_OverLimit → append_over_limit_drops_oldest_keeps_newest).

C5. Nothing is captured or shown while paused; the person can delete everything

  • Evidence: e2e_paused_nothing_captured_no_card, paused_nothing_captured (service),

e2e_forget_all_deletes_store_and_spool, e2e_forget_all_needs_confirmation.

  • Oracle: asserts zero stored events while paused and that the store and spool files are gone.
  • Confidence: Verified.

C6. The store keeps history as append-only facts and derives current state

  • Evidence: fact_tables_reject_update_and_delete (6 tables × update/delete → AIQ-STORE-APPEND-ONLY),

content_allows_delete_forbids_update, failing_migration_leaves_version_and_data_unchanged, rebuild_equals_live_working_set, rebuild_after_signal_does_not_fire_again, ready_card_expires_after_30_minutes.

  • Confidence: Verified.

C7. The daily cap holds for any clock or time-zone movement

  • Evidence: cap_never_exceeded_for_any_clock_moves (proptest over random clock jumps and offsets

−12 h…+14 h), timezone_move_back_does_not_reopen_used_day, daily_cap_reached_holds_then_resets_next_local_day, daily_cap_zero_never_shows.

  • Red observed: the first rule considered (count deliveries on an "effective day") was shown wrong by

reasoning before code (unbounded deliveries while the clock is behind); the property test encodes the invariant that rule breaks (DC-003).

  • Confidence: Verified.

C8. Local boundaries are guarded (STRIDE B1, B2, B4, B5)

  • Evidence: e2e_wrong_token_frame_closed_nothing_stored, authorize_wrong_or_missing_token_counted_no_request,

channel_full_drops_ingest_answers_take_card_null, read_line_capped_rejects_over_long_frame, store_file_is_owner_only, spool_file_is_owner_only, render_show_prompt_with_ansi_prints_sanitised, e2e_logs_never_contain_prompt_text (canary), e2e_install_uninstall_round_trip_byte_identical (other hooks kept, exec form with absolute command + args, never writes the working directory), e2e_install_invalid_json_refused_untouched, e2e_uninstall_after_user_edit_strips_only_aiq, e2e_copilot_shaped_payload_dropped_and_counted.

  • Confidence: Verified on Linux. Windows: the pipe code ran on the laptop and in Windows CI

(e2e_wrong_token_frame_closed_nothing_stored passes there); the laptop also showed the token check refusing hooks from a second AIQ home (DC-007), which is now explained by aiq status.

  • Residual risk: no peer-uid check on the Unix socket (0700 dir + token instead). Cross-account denial on

Windows is inferred from the DACL.

C9. Behaviour is measurable by default

  • Evidence: aiq status shows tips today vs cap, events by kind, signals, cards by state and reason, store

size, hook p50/p95 per event (in-process), spool backlog, hook and core error counters. Decisions are logged as JSON with trace_id (e2e_logs_never_contain_prompt_text asserts both).

  • Confidence: Verified.
  • Gap: the hook log records in-process time; whole-process time comes from the e2e test and the laptop run.
