Design: accuracy check of the rung judge

Produced with AI-Forward /design-slice. Imran picked this slice on 2026-11-02 ("Accuracy check on my tasks first", next-slice card) over the private alpha. Design only. No code in this change.

Goal state

Grounding

  • Rung-judge design, eval (measured 2026-11-02): 20 synthetic held-out tasks, exact 10/20, within

one 15/20, job 18/20. 11/20 Uncertain, 6 of them from F6. The design says: "Measure on Imran's real Copilot tasks first."

  • Fact-check rerun (PR #27, 15 hand-picked real Copilot sessions, model-graded): model facts 84/93; F4

10/15, F6 can't be settled on 9/15. Done by copying sessions into the cloud. That route does not scale and is not something AIQ users can do.

  • Coaching design: task-kind agreement is not measured (needs an eval rerun); thresholds are guesses.

The live type-guess self-check exists (auto-off below 8 of 10).

  • Rung-judge design, conformance notes: "Not measured yet: how often the judge picks ask_research

correctly" (pack added in PR #33).

  • Project rules: data stays on the device; judge calls go only to the provider that already saw the task,

under the person's own sign-in (ADR-0007); AIQ decides itself with an easy override (Imran).

Each rate prints as k of n with a 90% Wilson interval. Nothing prints as a bare percentage.

Data model

  • Bounded context: Rung assessment. New fact table `judge_check`, schema v7 (expand only).
  • Grain: one row is exactly one second reading of one judgment, identified by check_id (UUIDv7),

recorded when the grader call finishes.

  • Columns: check_id, run_id, judgment_id (by identity), task_id, grader_provider,

grader_model, answer (JSON: job, task type, rung, facts with value and can't settle), call_id, checked_utc_ms, check_version. Append-only trigger, as for judgment.

  • `judge_check_run`: one row is exactly one aiq judge --check run: run_id, seed, sample (JSON

list of judgment ids), requested, started_utc_ms.

  • Derive, don't store: every agreement number (A1–A5) and the pause rule (K6b) are computed from

judgment + judge_check. No stored percentages. Additivity: counts additive, rates non-additive.

  • History rule: rows are never updated; a new judge version gets new checks.
  • aiq forget --all and delete-one remove these rows too (they hold the grader's reading of the text).

Adversarial and privacy analysis

Same trust boundary as the judge (B5: core to the person's AI provider). Prompt-injection in task text can steer the grader as it can the judge: content is fenced the same way, and the grader's answer only changes a report and a pause, never a rung. The grader sees the same task text the provider already holds; a fuller excerpt (40k vs 18k) is a larger disclosure to that same provider, accepted under the person's run of the command. No new data leaves the device. Rows are deleted with the person's data.

  2. The thread that has the laptop builds main and gives Imran the upgrade line.
  3. aiq judge --check --dry-run (shows the sample and cost), then aiq judge --check. Laptop work is

Flagged risks

  • Model-graded agreement is not truth. A shared blind spot between judge and grader looks like a match.

Mitigation: blind reading, fuller excerpt, a stronger model where the plan allows; the label says so.

  • If Imran's plan forces one model for every Copilot call, grader and judge are the same model and

agreement will read high. The report shows this.

  • 30 tasks from one person is a small sample; intervals will be wide (for example 24 of 30 gives

roughly 66% to 90%, computed with the Wilson formula).

Deviations from the design (recorded, not silent)

  • K5: check calls do not count against the daily judge budget. The check is one command the person

runs, --dry-run shows the count and cost first, and counting it would starve background judging that day.

  • K3 (revised 2026-11-02 after the first run): the second reader is a different model from the **same

provider** (Imran). The first run used the judge's model on 29 of 30 because no Copilot model was set. Copilot CLI lists no model ids, so AIQ tries gpt-6-astra, then claude-sonnet-5.5, then gpt-5.6-sol. It skips any model the judge used. When Copilot answers "from --model flag is not available", AIQ moves to the next model for the rest of the run. That refusal takes about 8 s, measured. If no candidate is offered, Copilot picks the model itself. check-copilot-model overrides all of this. Claude Code stays opus, and the judge defaults to sonnet. Ids measured on Imran's laptop: recentModelIds, and a sealed --model claude-sonnet-5.5 call that answered as that model. His plan sets Sol as the default but does not lock it. The report still flags a same-model reading.

  • N2 (repeat stability): deferred. It needs a second judge run on the sample; add it once the first

numbers show whether it matters.

  • K6b (automatic pause): built 2026-11-02 after the first real runs; see "K6b: the automatic pause" below.

The Home "Judge check" card is still deferred (the CLI report carries the numbers).

  • Delete-one: check rows hold ids, the grader's job, type, rung and true/false/null facts, never task text,

so deleting one prompt's text needs no change here.

K6b: the automatic pause (built 2026-11-02)

AIQ decides; the person can override in one click or one command. Nothing new is stored: the pause is derived from check rows, judgments and one override setting each time the coaching cache is built.

#DecisionRuleMeasured or guessed
P1What pausesA pack's job (every next-step tip for a task AIQ guesses is in that job), or one kind of task (job and kind)Design choice
P2Job scoreOf the checked tasks the judge put in that job, how many the second reader also put in itSame count as the report's job agreement, split by the judge's job
P3Kind scoreOf the checked tasks the judge gave that kind, how many the reader gave the same job and kind. other kinds and no-job tasks are never scored (they never coach)Same count as the report's kind agreement (by_kind)
P4BarPause below 8 in 10Guess. The bar every AIQ rule uses (rung-model US-7, type-guess self-check, no-job and kind rules). Not measured: no repeat-run spread exists yet (N2)

A job with no checks at all (for example run_ship before its first check) is not pausedGuess. 10 is the run_ship gate (run-or-ship-pack P8); 5 is K6. At 10 checked, 7 of 10 has a 90% interval of about 45–88%, so a pause can be noise; the override is the remedy

Tests: domain (7 of 10 pauses a job, 8 of 10 doesn't, 9 checked is too few for a job but enough for a kind, a newer passing run resumes, a small newer run pools with the one before, no-job and other never scored); core (pause holds the tip with accuracy_paused, Keep showing brings it back, a newer failing check pauses again, a newer passing check resumes, Always on ignores it); UI e2e with axe (Home and Settings text, both buttons call the core with the right key).
