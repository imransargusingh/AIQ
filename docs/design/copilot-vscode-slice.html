Exposed

1. Copilot hook file ~/.copilot/hooks/aiq.json (whole file is AIQ's, so install and uninstall never edit another file's entries):

{ "version": 1, "hooks": {
  "userPromptSubmitted": [{ "type": "command", "exec": "<abs>/aiq.exe", "args": ["hook", "copilot", "userPromptSubmitted"], "timeoutSec": 5 }],
  "agentStop":           [{ "type": "command", "exec": "<abs>/aiq.exe", "args": ["hook", "copilot", "agentStop"],           "timeoutSec": 5 }]
}}

aiq hook copilot guarantees: always exits 0; never writes to stdout or stderr (Copilot shows nothing anyway, and stderr on exit 2 would change the agent); never opens the store. Both events are plain ingest frames: there is nothing to wait for at agentStop, because the tip is rendered by the status line. A payload is accepted as Copilot's only if it has camelCase sessionId and no hook_event_name (Claude Code's shape is refused, and vice versa). A hook process started with AIQ_INTERNAL=1 (AIQ's own future copilot -p judge calls) is ignored.

2. Status-line command aiq statusline copilot: reads stdin (cap 64 KB), finds the session id (field name from P2), sends tip_line, prints at most one line, exits 0. Budget: 100 ms p95 whole process, same as hooks; it does not block the agent, but it runs on every refresh. If the core is down, it prints nothing. It never starts the core (it may run very often).

3. Frames (added to the Phase 1 set; same token rule):

FrameReply
{"op":"tip_line","token","surface":"copilot-cli","session":<id or null>,"color":bool}{"line": string or null}
{"op":"take_card_any","token","surface":"vscode"}{"card": aiq.card.v1 or null}: delivers one show-ready card of any vscode session whose last event is a stop
{"op":"show",…}unchanged reply; now also appends card_open

tip_line with session = null (if P2 finds no id) uses the most recent show-ready or delivered copilot-cli card. simplify: ceiling: two Copilot CLI windows open at once could show one session's tip in the other; upgrade trigger: P2/P4 give a usable id.

4. Settings: aiq config set copilot-tip-stays next-prompt|two-prompts-or-5-min|until-opened.

5. Install: aiq install copilot writes ~/.copilot/hooks/aiq.json, and adds statusLine (+ experimental: true and STATUS_LINE in feature_flags.enabled, as the probe used; AIQ records what it turned on in copilot-install.json in its data folder, and uninstall turns off only that) to ~/.copilot/settings.json. On Windows statusLine.command is the path of AIQ's one-line wrapper ~/.copilot/aiq-statusline.cmd (the shape the probe proved); elsewhere it is "<aiq>" statusline copilot. Install applies these with the Phase 1 rules: show the diff, ask y/N, back up, temp-file-and-rename, refuse invalid JSON, refuse to replace an existing statusLine (print the line to add instead). Runs the installed hook once as a self-test and prints its time. aiq uninstall copilot removes the hook file and only an AIQ statusLine, the wrapper, and what the record says AIQ turned on. aiq install copilot --no-status-line (added 2026-11-02) installs the hooks only: no statusLine, no experimental or flag change, no wrapper; run over an earlier full install it takes AIQ's status line out and puts back what the record says AIQ turned on. Tips still show in aiq show, AIQ home and VS Code.

6. VS Code extension (extensions/vscode, publisher-less VSIX for the alpha, installed by code --install-extension): polls take_card_any every 2 s while a window is focused; shows the card as a non-modal information message; status-bar item; commands AIQ: Pause, AIQ: Resume, AIQ: Show tip details. No dependencies beyond @types/vscode and the TypeScript compiler. simplify: polling, not push; ceiling: 0.5 frames/s per focused window; upgrade trigger: a second VS Code consumer of core events (Phase 3 feedback) makes a subscription channel worth it.

How the pieces behave

Copilot CLI turn, end to end

  1. Person sends a prompt → userPromptSubmitted → aiq hook copilot → ingest (≤ 20 ms connect).

Core stores the event, runs the detector, maybe decides show-ready (Phase 1 table + quiet period).

  1. Agent works. The status line may refresh; the core sees the session's last event is a prompt, so a

show-ready card is not rendered mid-turn (spec: cards show only after the turn ends).

  1. Agent finishes → agentStop → ingest of a stop event.
  2. Status line refreshes → tip_line: the session's last event is a stop and a show-ready card exists

→ re-check budget (paused, session, daily cap, quiet period) → insert card_delivery → reply AIQ tip: you've reworded this 3 times without new details · aiq show 01J….

  1. Later refreshes reply with the line, the waiting marker, or nothing, per tip_line_state.

The status line refreshes after the agent's turn ends: run 2 saw it run 1 s and 2 s after agentStop (Verified, run 2). It also refreshes on prompt submit and while the agent works; step 2 keeps those silent.

Trigger engine change

One check is added to in_moment.v1 (becomes in_moment.v2 in the pack, so old decisions keep their rule id), after session_budget and before one_at_a_time:

CheckOutcomeReason code
A card was delivered on any surface less than quiet_min (30) minutes agoholdquiet_period

may_deliver gains the same check. A card held for quiet_period is not retried later (Phase 1 holds are final; the next qualifying signal decides afresh).

VS Code

The hook client sets surface = "vscode" when COPILOT_CLI_RUN_AS_NODE is set and COPILOT_LOADER_PID is not (P3, run 2), else copilot-cli. If Copilot changes these names, VS Code turns fall back to copilot-cli: their tips wait for a CLI status line in that session, which never asks, so they expire unseen. No data is lost and the budget holds; AIQ-TIPLINE-NEVER-ASKED counts it. In VS Code each agent turn is its own Copilot session (sessionEnd reason complete after every agentStop), so the reword detector, which works within a session, will rarely fire there until it looks across sessions. The extension's poll takes VS Code cards after the turn ends; status bar shows AIQ · AIQ paused · AIQ: 1 tip. simplify: with several VS Code windows open, the first focused window to poll shows the card; ceiling: one person, a few windows; upgrade trigger: a payload field that ties a session to a window.

UI and interaction design

Copilot CLI status line (terminal medium). One line, ≤ 100 columns, plain words first:

AIQ tip: you've reworded this 3 times without new details · aiq show 01J…
1 tip waiting · aiq show 01J…

No colour carries meaning; with colour on, "AIQ tip:" is bold yellow as in Claude Code; NO_COLOR gives plain text. Never quotes prompt text. aiq show prints the full card (Noticed / Why / Try this / evidence), records the open, and ends with Turn off tips for now: aiq pause.

VS Code. Non-modal showInformationMessage (never steals focus, announced by screen readers): "AIQ tip: you've reworded this request 3 times without adding new details. Try this: say what was wrong with the last answer, and add one example, file or constraint." Buttons: Details, Pause AIQ. Status-bar item text and accessible label: "AIQ on" / "AIQ paused" / "AIQ: 1 tip waiting"; click opens a quick pick (Show tip · Pause/Resume). Pause in ≤ 2 steps from the status bar.

Follow-up: automated sessions ignored live (2026-11-01)

Copilot hooks are user-level, so an app's pipeline that calls Copilot (Executive_Presence, ~6,000 sessions) would reach AIQ. Live side of the import spec's automated rule (history import, US-12, H4), decided at a session's first prompt:

  • NI (Claude Code, in the hook): CLAUDE_CODE_ENTRYPOINT starting sdk (a claude -p / SDK run)

records nothing. assume: hooks inherit it like other children of Claude Code; if not, B/T still apply.

  • B / T (core, every surface): 50+ sessions started in one folder within 30 minutes, or the same

normalized first prompt in 11+ sessions there within 24 hours. The folder is then set aside (folder_rule, schema v3, append-only; newest row per folder wins; shared with import).

  • F: later sessions in a set-aside folder are ignored at their first prompt. H ≥ 2: a second
