Design: the Run or ship it pack

Produced with AI-Forward /design-slice. Drafted before Imran's decision, under his standing rule: it is cloud-only and changes nothing anyone sees. If he says no, this stays a draft and nothing is built.

Goal state

GoalCoach the tasks where the person runs, ships or sets up a system, which no pack covers today
Done whenThe judge names the job; a different-model check agrees on it at least 8 of 10; its tips can fire
Not in scopeA pack for chat or tests, planning, or brainstorming (each 3 of 30 or fewer); changing the other three packs
TierT1 (new job value, judge version bump, pack data; no schema change)

Grounding (measured unless marked)

  • No job: 101 of 473 judged tasks. Of those, 76 had both runs say other. A different model agreed they

are other 18 of 18 (check run 01a19d99). So these tasks are outside every pack, not misread.

  • Survey of 30 of the 76 (aiq judge --survey-other, 2026-11-02 19:39Z): operate systems 17, set up

tools 3, chat or test 3, plan or manage 3, other 2, learn or brainstorm 1, review or feedback 1. The kinds are Inferred (one model's reading, no person).

  • Labels for operate systems: application restart troubleshooting, package application release, publish

clean project repository, publish project source, refresh data and launch. For set up tools: authenticate tool connection, network access configuration.

  • Scaled (worked out, not measured): operate systems plus set up tools is 20 of 30, so about 51 of the 76

tasks (Wilson 90%: 52% to 79%, so 39 to 60), or about 11% of all judged tasks.

Decisions

#QuestionDecisionWhy
P1What is the job?`run_ship`, "Run or ship it": the result is a system in a new state, not changed files and not an answer. Start, restart or fix a running app; package, release, publish or deploy; run a script, pipeline or data refresh; install, connect or configure a tool or environmentOne job for both kinds the survey found. "Set up tools" is the same shape of work (act on a system, then check it took), and 3 tasks alone would never reach the 3-repeat coaching minimum
P2Where is the line with code_change?If the person's goal is edited code or config in the repo, it is code_change, even if they then run it. If the goal is that something runs, ships or connects, it is run_ship, even if a file changes on the wayMatches how code_change already keeps incidental doc edits. The judge prompt states it in one line
P3Task typesrestart_fix (get a stopped or broken thing running), release (package, publish or deploy), run_job (run a script, pipeline or data refresh), setup (install, connect or configure a tool), otherCovers every survey label for the two kinds. Few types, so the judge can name them confidently
P4Which facts?The shared F4, F5, F6, F7, F12, F13. "The agent did it itself" reads F14 (the agent read, searched, fetched or ran something), as Ask or research does, not F1 (the agent edited files). Sub-agents read F15Running commands is what the agent does in this job, and F14 is already measured from the log. No new fact, so no new log reader
P5Rungs for this job1 Assisted: you ask for one command at a time and run it yourself. 2 Directed: you say what should be running, where, and what must not break, and you check it took. 3 Delegated: you hand over the whole release or run with a done check, and the agent runs the commands itself. 4 Orchestrated: a written runbook, with an automated check between steps. 5 Factory: a versioned script or pipeline that others can triggerThe shared ladder, worded for this job (rung-model R5)
P6Tips (moves)See the table below. All step 1 and 2 moves are job-specific. Step 3 and 4 reuse the any moves written_brief and split_and_checkThe same pattern the other packs use
P7SafetyThe check tip (F6) comes before the hand-over tips in pack order. The hand-over tip names a limit ("not production" or "stop before the publish") in its starter. No tip tells anyone to let an agent act on production uncheckedMistakes here can reach live systems, which costs more than a wrong file. Ties go to the earlier move
P8Going liveJudge version j5. Only j4 judgments where both runs said other are judged again (76 tasks, 2 calls each, about 152 calls: under Imran's daily cap). Then aiq judge --check must agree on run_ship at least 8 of 10, with at least 10 checked. Until then the job's judgments are Uncertain and drive no coachingThe same bar as every other pack (rung-model US-7)
