Design: AIQ home deferred pages

Produced with AI-Forward /design-slice (v2026.10.19.4). Builds on docs/design/aiq-home-app.md (Phase 3, D1 deferred these three screens) and implements docs/specs/aiq-home.md US-H1, US-H4 (the parts that need no judge) and US-H6 (delete one item).

Goal state

GoalIn AIQ home the person can open one task and see its prompts, is walked through setup on first run, and can delete one captured prompt
Done whenRust tests prove the task detail read, the setup flag, and that a deleted prompt's text is gone from the store file, its WAL and the core's memory; the UI e2e covers each screen and its states with 0 axe violations in light, dark and high contrast; CI green
Not in scopeAnything the rung judge feeds (rung, facts, why, next step, starter prompt, "This doesn't fit"): placeholders only. Installing hooks from the app. Starting preset (no presets exist yet). Delete older than a date. Deleting one imported prompt. Laptop check (another thread is using the laptop)
TierT2 (a new write path that deletes the person's data)

Decisions

#QuestionDecisionWhy
E1What does "delete one item" delete?The prompt's text (the content row). The event row stays: that a prompt was sent, when, from which tool and folder, and its length. Your data then shows "Text deleted", and card evidence says the evidence was deleted (already built in aiq show)event is an append-only fact table by design, and task counts must stay true. The text is the person's content (ADR-0002: "raw prompts stay until the person deletes them"). The confirm dialog says exactly what stays
E2Is the deletion real?Yes, at every place the text lives: the row is deleted with secure_delete on (freed pages are zeroed), the WAL is checkpointed and truncated, and the core rebuilds its detector working set so the text leaves its memory"Deletion must be real" (project rule). SQLite otherwise keeps deleted bytes in free pages and in the WAL
E3Who writes the delete?The core, through a new local API frame ForgetItem. When the core is not running, AIQ home opens the store and deletes directly, the same way delete everything deletes files when the core is downThe core is the single writer and holds prompt text in memory. With the core down nobody else writes, and the person isn't made to start it first
E4Which items can be deleted one by one?Live prompts listed on Your data that still have textImported prompts are copies of the tool's own history file, which AIQ doesn't own; deleting AIQ's copy would come back on the next import of a changed session. aiq forget --imported already deletes all of them. Flagged as a follow-up
E5How does AIQ home know setup ran?A setup-done flag file in the data folder (user-only), written by AIQ home, read into status.setup_doneSetup must finish on a fresh install, before the core has ever started (the core starts with the first prompt). A core setting would make setup fail exactly then. It is app state, not the person's data, so delete everything keeps it
E6What does setup ask?Five steps, each with Back: (1) the privacy promise, (2) the tools AIQ found, (3) the rung judge, (4) tips a day, (5) the lost-machine notice with "I understand", which enables StartSpec US-H1 order. The judge does not exist yet, so step 3 says what it will do and that there is nothing to connect now (design G2). Tips a day is written through the core; with the core down the step says the default (5) stays and Settings can change it later
E7How does setup find tools?aiq_core::tools: Claude Code hooked (AIQ's entries in the Claude Code settings file), Copilot hooked (hooks/aiq.json in the Copilot home; VS Code agent mode uses the same hooks). Not hooked shows the one aiq install … commandOne definition shared with the CLI's install and status (moved from the aiq crate, not copied)
E8Where is task detail?#task/<id> from the Tasks page (Enter or click on a row). It shows when, tool, folder, prompts, imported or live, the prompts in order, and the judge sections with "Not judged yet"Spec US-H4, minus what needs the judge. The rung judge thread fills the judge sections later in the same places
E9How is the detail read?A new command task(task_id): the same task read as the snapshot (one shared function), then the text of that task's promptsOne Task rule; the snapshot stays small (no prompt text per task)

Flagged risks

  • If the core starts in the moment between "not running" and AIQ home's direct delete, the core read the

text at start, so its detector keeps word sets from that prompt in memory until it next restarts or the task goes idle (30 minutes). The store and disk are clean either way. Accepted (narrow window; memory only).

  • Imported prompts can't be deleted one by one (E4). Flagged as a follow-up.
  • Setup can't connect a tool itself; it names the aiq install command. Installing from the app means

AIQ home editing other tools' settings files, a new trust step. Flagged as a follow-up.

  • Real WebView2 keyboard and screen-reader pass for the three screens is a laptop check, not done here

(another thread is using the laptop). Flagged.

Gate record

GATE design-slice · 2026-11-02 · Patterns, Simplifier, Test Architect, Security, Data & Persistence, UX & Accessibility (seats played by Claude in one session; not independent) · verdict: pass with conditions

  • Data & Persistence (hard): no schema change; event facts stay append-only; content deletion was already the designed path (content: "delete only by the person"). Pass.
  • Security (hard): deletion verified at the byte level, not only the row. Pass; condition: the raw-file test must fail if secure_delete or the checkpoint is removed.
  • Privacy: what stays after a delete is said in the dialog (E1). Pass.
  • Simplifier: setup flag is a file, not a new table; no router (hash). Pass.
  • UX & Accessibility: setup is serial (enter), detail is reading (parallel), per archetype H1. Laptop WebView2 check owed later.
