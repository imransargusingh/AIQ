Read

TaskDetail.tips (crates/aiq-home/src/detail.rs):

  • shown: Tip history's own rows whose task_id is this task, so both pages always agree. TipRow gains

task_id and answer.

  • held: the newest decided card for the task with no delivery; its newest decision's reason in words

(funnel::words) and what helps (funnel::help, which gains daily_cap).

  • step, step_words, step_help: the funnel's newest step for the task.

Surface

One card between "How this task was done" and the prompts (clear of the Kind chip in the analysis card). One view, in order: shown tips; else the held tip and why; else why no tip. Imported tasks say tips are for live work. An open task whose label is still on its way says AIQ is still working out its kind, not that the label was lost. A task with no recorded step says "AIQ didn't record why", never a guessed reason.

Team tips. The "Tool to try" line is read from the team file by tip_id when the page opens, as Tip history does. The store keeps only the entry id and fingerprint; team tip text is never stored.

Tip history. Each row offers "Open its task" when the newest showing's task is still in the Tasks list.
